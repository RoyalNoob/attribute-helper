# attribute-helper

[English](README.md) | **日本語** | [繁體中文](README.zh-TW.md)

Houdini 22 用の Python Panel です。各 SOP アトリビュートがどこで生まれ（Born）、書き換えられ
（Written）、そのまま通過し（Pass-through）、削除される（Deleted）かを、ネットワークエディタ上に
オーバーレイで表示します。さらに、サブネット・HDA・ネットワークボックスが外へ漏らしている
アトリビュートをレポートし、各項目を「意図どおり」としてマークできます。

Houdini にはアトリビュートのスコープがありません。ノードが作ったものはすべて下流へ流れていきます。
このパネルはそれを可視化し、サブネットから漏れた一時アトリビュートや、上書きされてしまった
外側のアトリビュートを見つけやすくします。

ステータス：プレアルファ。[docs/plan.md](docs/plan.md) の 6 フェーズはすべて完了しています。
対応は Houdini 22 のみです。

![mask にチェックを入れた Lifetime タブ：Wrangle で生成、Attribute Delete で削除、Merge を通過](docs/images/hero.png)

> UI の表記は英語です（Houdini の UI に合わせています）。本書ではボタン名などを英語のまま記載します。

## インストール

1. このリポジトリを任意の場所に置きます（clone またはダウンロード）。
2. Houdini で **Windows** > **Python Shell** を開き、次の 1 行を実行します。
   `<path-to-attribute-helper>` は、リポジトリを置いたフォルダに置き換えてください。区切りは
   スラッシュ `/` を使います（例：`D:/tools/attribute-helper`）。

   ```python
   import runpy; runpy.run_path(r"<path-to-attribute-helper>/install.py")
   ```

   インストール先が表示されます。書き込まれるのは
   `<Houdini の設定フォルダ>/packages/attribute_helper.json` という小さなファイル 1 つだけで、
   Houdini にこのフォルダの場所を教えるものです。
3. Houdini を再起動します。
4. パネルを開きます：任意のペインで **+** > **New Pane Tab Type** > **Inspectors** >
   **Attribute Helper**。ネットワークエディタの隣に置くと便利です。

リポジトリを移動した場合は、新しい場所からもう一度インストールの 1 行を実行してください。

<details>
<summary>手動でインストールする場合</summary>

Houdini の設定フォルダ（`$HOUDINI_USER_PREF_DIR`。Windows では通常 `Documents/houdini22.0`、
Linux では `~/houdini22.0`、macOS では `~/Library/Preferences/houdini/22.0`）の `packages`
フォルダに `attribute_helper.json` を作成します。`<path-to-attribute-helper>` は上と同様に
置き換えてください。

```json
{"package_path": "<path-to-attribute-helper>/package"}
```

Windows では、スタートメニューから起動した Houdini は `Documents/houdini22.0` を読みますが、
`HOME` が設定されたシェル（Git Bash など）から起動すると `$HOME/houdini22.0` を読みます。
インストールスクリプトは、起動中の Houdini 自身に設定フォルダの場所を問い合わせるので、
この問題は起きません。

</details>

## クイックスタート

1. ノードがいくつかあり、ディスプレイフラグが立っている SOP ネットワークに入ります。
2. **Lifetime** タブに、ディスプレイノードより上流のチェーンにあるすべてのアトリビュートが
   一覧表示されます。
3. アトリビュートにチェックを入れると、そのライフタイムがネットワークエディタ上に描画されます。
4. サブネットを調べるには、サブネットを選択して **Leak report** タブを開き、
   **Use selected subnet / HDA / box** をクリックします。

## Lifetime タブ

### ターゲット

パネルは 1 つの**ターゲット**ノードと、同じネットワーク内でそれより上流にあるすべてのノードを
対象にします。

- **Follow display node**（既定）：エディタが表示しているネットワークのディスプレイノードが
  ターゲットになります。ネットワークに出入りしたり、ディスプレイフラグを移したりすると追従します。
- **Use selected**：選択中の SOP をターゲットに固定します。固定を解除するには
  **Follow display node** に再びチェックを入れます。

フィルタの下の行に、ターゲットと読み込んだノード数が表示されます。

### Cook on demand

ノードのジオメトリを読むとクックが始まることがあり、重いシーンでは時間がかかります。

- **オフ**（既定）：すでにクック済みのノードだけを読みます。クックが必要なノードは対象外となり、
  その数がステータス行に表示されます。含めたい場合は、そのノードを表示するか、このオプションを
  オンにします。
- **オン**：必要に応じてノードをクックします。

**Refresh** はパネルのキャッシュを消去し、すべてを読み直します。通常は不要です。パネルは表示中、
1 秒に 4 回変更をチェックし、再クックされたノードだけを読み直します。

### テーブル

チェーン内のアトリビュート（およびグループ）ごとに 1 行です。

| 列 | 意味 |
|---|---|
| Show | チェックを入れると、そのアトリビュートのライフタイムをネットワークエディタに描画します。チェックの色が描画色です。 |
| Name, Class, Type | `point`、`prim`、`vertex`、`detail`。グループは `group:point`、`group:prim`、`group:vertex`、`group:edge`。 |
| Born | それを作るノード。サブネット内のノードは `subnet1/node` のように表示されます。 |
| Deleted | それを削除するノード。 |
| Written | それを変更するノードの数。目安です：[状態](#状態)を参照。 |
| Rebuilt | それが残ったままトポロジを作り直すノードの数（そこでは書き込みを検出できません）。 |

フィルタ：

- **Name filter**：普通の文字列は名前の一部に一致します（`mas` で `mask` が見つかります）。
  `*`、`?`、`[...]` はワイルドカードとして使えます。
- **Class**：1 つのクラスだけを表示します。
- **Hide standard**（既定でオン）：`P`、`N`、`Cd`、`uv`、`v`、`id`、`pscale`、`orient`、`name`
  などの一般的なアトリビュートを隠します。

列見出しをクリックすると並べ替えます。行の名前をクリックすると、そのアトリビュートが生まれた
ノードを選択します。サブネット内で生まれた場合は、エディタがそのサブネットへ移動します。

![アトリビュートをクリックすると、サブネット内であっても生成元のノードへ移動します](docs/images/nav.gif)

### オーバーレイ

チェックしたアトリビュートごとに色が割り当てられます（8 色、それ以降は繰り返し）。
そのアトリビュートについて：

| ネットワークエディタ上の表示 | 意味 |
|---|---|
| 塗りつぶしの枠 | ここで **Born**（生成） |
| 実線の枠 | ここで **Written**（書き込み） |
| やや薄い枠 | ここで **Rebuilt**（トポロジが変化） |
| かすかな枠 | 変更なしで **Pass-through**（通過） |
| バツ印つきの枠 | ここで **Deleted**（削除） |
| 色付きのワイヤ | アトリビュートがこのワイヤを通って流れる |

複数のアトリビュートにチェックを入れると、枠は入れ子になり、ワイヤは横に並びます。オーバーレイは
ノードをドラッグすると追従し、ターゲットのあるネットワークにだけ表示されます。ノードの色など
シーンの内容は一切変更しません。パネルを閉じると消えます。

![P と mask の 2 つにチェック：それぞれ別の色で表示](docs/images/two-attributes.png)

### サブネットと HDA

チェーンには、**編集可能な**ネットワーク（通常のサブネットとロックされていない HDA）の内部も
含まれます。内部で作られたアトリビュートは実際の生成場所（`subnet1/attribwrangle1`）が表示され、
外側の階層ではサブネットの枠がその全体の効果を示します（たとえば内部で何かが生成されれば「born」）。

**ロックされた HDA は 1 つのノードとして扱います。** HDA として作られている SideFX のノード
（Attribute Wrangle、Solver など多数）も同様で、内部のノードでテーブルが埋まることはありません。
ロックされた HDA を外側から調べるには Leak report を使ってください。

## 状態

パネルはノードごと・アトリビュートごとに、そのノードのジオメトリと入力のジオメトリを、Houdini の
アトリビュートごとのデータ ID を使って比較します。

| 状態 | 意味 |
|---|---|
| Born | どの入力にもなく、ここにある。 |
| Written | 入力にあり、ここにもあり、データが変化した。**目安です**：値を変えずにデータだけ変えるノードもあります。 |
| Pass-through | 入力から変化していない。 |
| Rebuilt | ここにあるが、ノードがトポロジを変更した（Blast、2 入力の Merge、Copy to Points、Pack、Clean、For-Each など）。このときすべてのアトリビュートが新しいデータになるため、書き込みとコピーを区別できません。 |
| Deleted | ノードの**第 1 入力**にあり、ここではなくなった。ほかの入力にしかないアトリビュート（Wrangle の第 2 入力、Copy to Points のポイントなど）は読まれるだけで引き継がれないため、「削除」とは見なしません。 |

クックに失敗したノードや、**Cook on demand** がオフでクックが必要なノードには状態がありません。
比較対象がないため、その直後のノードにも状態はありません。

## Leak report タブ

リークレポートは、1 つの**スコープ**を 1 つのステップとして扱い、出ていくものと入ってきたものを
比較します。

### スコープの選び方

ネットワークエディタでスコープを選択し、**Use selected subnet / HDA / box** をクリックします。

- **サブネットまたは HDA**（ロックの有無を問わず）：入力から出力までを比較します。
- **ネットワークボックス**：ボックス内のノード（入れ子のボックスを含む）。入力はボックスに入ってくる
  ワイヤ、出力はボックスの外へ出ていくノードです。出口が複数あるボックスでは出口ごとにレポートが
  作られます（「Exit: …」）。外へ出るものがない場合は、ボックス内の最後のノードが出力になります。

ボックスとノードの両方を選択している場合はボックスが使われます。タブが表示されている間、
レポートはリアルタイムに更新されます。

![ネットワークボックスをスコープにした例：出口ごとにレポート](docs/images/network-box.png)

### 検出項目

| セクション | 意味 |
|---|---|
| Leaked locals | 内部で作られ、出力まで残っている。 |
| Outer writes | 外から入ってきて、内部で変更された（Written と同じく目安）。 |
| Deleted outer attributes | メイン入力から入ってきて、内部で削除された。 |
| Unknown | 外から入ってきたが、内部でトポロジが変わったため書き込みを検出できない。 |

### 意図どおりの項目をマークする

すべての検出項目が間違いとは限りません。サブネットはアトリビュートを出力するために作られることも
よくあります。**意図どおり**の項目にチェックを入れてください。チェックのない項目は赤いまま残り、
ステータス行にその数が表示されます。赤く残ったものが修正すべき箇所です。

![サブネットのリークレポート：tmp は意図どおりにチェック済み、mask と mask_1 は赤のまま](docs/images/leak-report.png)

- チェックは **leaked**（漏出）、**changed**（変更）、**deleted**（削除）の 3 種類の意図のいずれかを
  表します。Outer write と Unknown はどちらも「changed」として扱うので、後から Merge を追加して
  書き込みが Unknown に変わっても、チェックは保たれます。
- どの項目にも一致しなくなったチェック（たとえば、そのアトリビュートを作っていたノードを削除した
  場合）は **Marked intended, no longer found** に表示されます。チェックを外すと消えます。
- チェック 1 回が 1 つのアンドゥ操作です：「Attribute Helper: mark finding intended」。

チェックの保存先：

- **サブネットまたは HDA**：そのノード上の非表示の文字列パラメータ `attribute_helper_intended`。
  最初にチェックしたときに作られ、hip ファイルと一緒に保存されます。HDA の場合はそのノードの
  スペアパラメータであり、HDA の定義には含まれないため、インスタンスごとに別々のチェックを
  持ちます。パラメータペインには表示されませんが、Edit Parameter Interface で確認できます。
- **ネットワークボックス**：ボックスにはパラメータがないため、同じ非表示パラメータをボックスを含む
  ネットワーク側に作り、ボックス名の下に 1 項目 1 行で保存します。
  **ボックスの名前を変えるとチェックは失われます。**

保存される文字列は 1 項目 1 行の `<scope> <intent> <class> <name>` 形式です（例：
`. leaked point tmp`）。パネルが書き込むので、手で編集する必要はありません。

これが、このツールがシーンに加える唯一の変更です。

## 既知の制限

- SOP のみ対応。
- 読み取りは検出しません：ノードが読むだけのアトリビュートは Pass-through に見えます。
- 「Written」は目安であり、「Rebuilt」「Unknown」は値が変わったかどうかを判断できません。
- 入力が複数あるノード（Merge）では、オーバーレイのワイヤは正確な入力コネクタではなく、ノード上端の
  中央で終わります。
- 出力が複数あるサブネットは、第 1 出力からのみたどります。
- ネットワークボックスの名前を変えると、そのチェックは失われます。
- ネットワークエディタを複数開いている場合、ターゲットは最初のエディタに追従します。

## アンインストール

インストールスクリプトが表示した `attribute_helper.json`（Houdini 設定フォルダの `packages` 内）を
削除し、Houdini を再起動します。チェックを入れたノードには非表示の `attribute_helper_intended`
パラメータが残ります。必要なら Edit Parameter Interface で削除してください。
